# Бэрримор

**Локальная система непрерывности.** Один постоянный дворецкий, много сменяемых работников.

Бэрримор помнит ваши нити и разговоры, знает, какие агенты установлены на машине,
готовит им поручения, запускает их в изоляции и принимает результат. Он работает
на вашем компьютере, на локальной модели, и ничего не делает без вашего ведома.

Это не очередной coding agent и не чат с памятью. Личность, память, решения и
границы принадлежат runtime, а не языковой модели: модель можно сменить, и
Бэрримор останется собой. Метафора «дворецкого» описывает устройство управления
и не является заявлением о сознании.

## Что нужно

| | |
|---|---|
| Linux | проверено на Debian 13 |
| Go 1.25+ | для сборки |
| `bubblewrap` | без него поручения не запускаются: чтение-без-изменений обеспечивается изоляцией ядра, а не просьбой к исполнителю |
| пользовательский `systemd` | надёжная идентичность процессов и супервизия |
| `llama-server` из llama.cpp | если хотите локальную модель |
| модель в формате `.gguf` | любая, которую тянет ваша машина |

Внешние агенты (opencode, hermes, codex, claude) необязательны: без них работают
нити, память, разговор и предиктивный контур. Бэрримор честно покажет, кого нашёл,
а кого нет.

## Установка

```bash
make install
```

Кладёт `barrymored` в `~/.local/bin` и пользовательскую службу systemd. Затем:

```bash
systemctl --user enable --now barrymore
```

Откройте <http://127.0.0.1:7717>.

Никакого root: Бэрримор работает с личными данными и не нуждается в правах на
всю систему.

## Первый запуск

`barrymored` без единого флага сам находит `llama-server`, каталог моделей и
число потоков CPU, замечает видеокарту — и говорит в журнале, что именно нашёл.
Если модель в каталоге одна, он её выберет; если несколько — выбор оставит вам.

Двух вещей он себе не выдаёт:

- **разрешённые рабочие каталоги.** Доступ ко всему диску не является значением
  по умолчанию, и выписывать себе доступ к чужим каталогам по догадке нельзя.
  Задайте их в разделе «Настройки» — изменение действует сразу.
- **распределение экспертов MoE.** Оно зависит от устройства конкретной модели,
  и число «на глаз» сделает хуже, а не лучше.

## Как этим пользоваться

**Приёмная** — разговор. Бэрримор отвечает, предлагает записать что-то в память,
предлагает поручения и задаёт открытые вопросы. Ничего из этого он не делает
сам: всё возвращается вам как предложение.

**Нити** — то, чем вы заняты, сгруппированное по-человечески: «Сейчас живёт»,
«Зреет», «Ждёт», «Застряло», «Мы не договорили», «Завершено», «Отпущено».
В карточке нити позиции сторон стоят в двух колонках: ваша и его. Они могут
не совпадать, и это нормально — Бэрримор умеет аргументированно не согласиться.

**Штат** — кто установлен, что подтверждено наблюдением, а что только заявлено,
какие модели бесплатны и когда это проверялось.

**Поручения** — зачем, кому, почему именно ему, что разрешено, что получилось.
Первое поручение всегда только на чтение.

**Память** — что записано и почему. Бэрримор сам решает, что запомнить: он
указывает тип, чувствительность и уверенность, а политика решает по ним.
Чувствительное и сомнительное выносится вам. Вы можете сказать «запомни это»
напрямую и удалить любую запись.

**Настройки** — какую модель поднимать, как она считает, кого привлекать
из исполнителей, какие каталоги им видны.

**Технический режим** — переключатель в шапке. Показывает идентификаторы, виды
событий и внутренние состояния. Без них невозможен разбор происшествия, поэтому
они скрыты, а не удалены.

## Что он делает с вашей безопасностью

- Поручение на чтение **действительно** только читает: рабочий каталог
  монтируется read-only через bubblewrap. Неизменность проверяется после
  запуска, а не обещается заранее.
- Учётные записи исполнителей не читаются и не копируются — только
  подмонтируются им же, на чтение.
- Ключ внешнего провайдера берётся только из окружения: в командной строке он
  был бы виден в списке процессов.
- Интерфейс по умолчанию слушает только петлевой интерфейс.
- Бесплатность модели определяется **до** запуска, по пометке провайдера в
  названии. Появившееся списание означает, что провайдер изменил условия:
  работа немедленно прекращается, а модель навсегда перестаёт считаться
  бесплатной.
- Удаление записи из памяти затирает содержание, но оставляет в журнале
  отметку о том, что запись была и была удалена. Интерфейс говорит об этом
  прямо, а не делает вид, что данные исчезли бесследно.

## Локальная модель

Бэрримор держит `llama-server` сам: наблюдает раз в 15 секунд, отличает загрузку
весов от отказа, при пропаже поднимает заново — три попытки, дальше спрашивает вас.
Бесконечный перезапуск скрывал бы настоящую причину: нехватку памяти, испорченный
файл весов, занятый порт.

Сервер переживает перезапуск Бэрримора: повторная загрузка 20 ГБ весов заняла бы
минуты без всякой пользы. Если сервер уже работает, а Бэрримор его не запускал,
он так и скажет и не станет ни останавливать его, ни поднимать второй.

Сменить модель можно на ходу, в «Настройках». Порт — нельзя без перезапуска,
и об этом сказано прямо: разговорный слой настроен на конкретный адрес.

## Состояние

Честный статус — в [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

Работает: полный контур делегирования на реальных агентах, разговор на локальной
модели, память с собственным решением Бэрримора, надзор за моделью, продуктовый
интерфейс, восстановление после перезапуска.

Не сделано: изменение кода исполнителями (пока только чтение), инициатива
Бэрримора, E2E-тесты интерфейса.

```bash
make ci
```

Форматирование, статические проверки, тесты с детектором гонок, сборка.

Запуск из репозитория без установки:

```bash
make run
```
