### Почему codex выбран первым

`codex exec` предоставляет ровно те точки контроля, которые требуют
`docs/05_STAFF_AND_DELEGATION.md` и `docs/08_API_AND_EVENTS.md`:

| Флаг | Назначение в Бэрриморе |
|---|---|
| `--json` | JSONL-поток событий → типизированные `RunEvent` без парсинга человекочитаемого вывода |
| `--sandbox read-only` | второй слой защиты audit-only поверх `bwrap` |
| `-C <dir>` | рабочий корень |
| `--output-schema <file>` | JSON Schema обязательного отчёта |
| `-o <file>` | последнее сообщение агента как артефакт |
| `--skip-git-repo-check` | запуск вне git-репозитория |
| `--ephemeral` | не писать сессию на диск |
| `--ignore-user-config` | воспроизводимость: не наследовать `~/.codex/config.toml` |

`claude` в PATH отсутствует, поэтому пример манифеста `claude-code` из
`docs/08_API_AND_EVENTS.md` §5 остаётся иллюстрацией. См. ADR 0005.

**Секреты.** Бэрримор не читает и не копирует `~/.codex/auth.json`. Дочерний процесс
пользуется собственной аутентификацией через `CODEX_HOME`. В базе хранится только
`SecretRef` вида «worker пользуется своей учётной записью», без значения.

## 5. Локальная модель

| Параметр | Значение |
|---|---|
| Файл | `data/local_models/Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` |
| Размер | 22 134 528 992 байт (20.6 GiB) |
| Формат | GGUF v3, 733 тензора, 54 KV |
| Архитектура | `qwen35moe` |
| Блоков | 40 |
| Экспертов | 256, активны 8 |
| Embedding | 2048, головы 16 / KV 2 (GQA) |
| Контекст обучения | 262144, rope freq_base 1e7 |

Перенесён в data root проекта по решению владельца (rename в пределах `/dev/sdb2`, мгновенно).
Исключён из git через `/data/` в `.gitignore`.

Оценки до замеров: KV-кэш ~40 KB/токен при f16, поэтому рабочий контекст ограничивается 32k
(~1.3 GiB), а не 262k (~10 GiB). Активных параметров ~3B → генерация упирается в пропускную
способность памяти; prefill упирается в CPU и является узким местом для длинных ContextPack.

`llama-server` не установлен. Архитектура `qwen35moe` требует свежей сборки llama.cpp —
это проверяется спайком S1, см. ADR 0012.

## 7. Что аудит не проверял

- параметры RAM (каналы, частота) — требуется `dmidecode` и root, passwordless sudo отсутствует;
- фактическую доступность квот у codex/opencode — это платный или полуплатный запрос,
  выполняется только по policy на этапе 3;
- сетевую политику исходящих соединений;
- целостность существующих репозиториев-кандидатов.
