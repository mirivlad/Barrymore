# ADR 0016: Контролируемая запись происходит в копии, а не в каталоге владельца

Status: Accepted
Date: 2026-08-05

## Context

До сих пор Бэрримор умел только смотреть. Поручение с правом записи означало
бы, что исполнитель работает прямо в каталоге владельца, — а исполнитель это
внешний инструмент, чьё поведение Бэрримор не контролирует и чьи сообщения
считает недоверенными (ADR 0002).

05_STAFF_AND_DELEGATION §10 требует: зафиксировать исходный HEAD, не уничтожать
существующую работу, запретить push, проверить изменения и сделать слияние
отдельным действием.

## Decision

### До решения владельца его каталог не трогают вообще

Исполнитель получает полную копию рабочего каталога. Пишет он в неё. Каталог
владельца не открывается ему даже на запись — его в песочнице попросту нет.

Из этого следует главное: проверка «каталог владельца не изменился» остаётся
в силе и для поручений с записью. Не как обещание, а как факт, который сверяется
слепком после запуска.

### Копия, а не `git worktree`

Worktree выглядит уместнее, но создаёт записи внутри `.git` настоящего
репозитория. То есть уже меняет каталог, неизменность которого Бэрримор потом
проверяет, и делит с исполнителем объекты git. Полная копия дороже, зато
говорит правду: пробой изоляции не достанет до оригинала.

Ограничение честное: копирование стоит времени и места, и на каталоге больше
200 000 файлов Бэрримор отказывается, а не копирует молча полчаса.

### Копируется всё, включая незакоммиченное

Иначе исполнитель работал бы не с тем, что видит владелец, и расхождение
вскрылось бы в самый неудачный момент — при применении.

Состояние «до» фиксируется коммитом внутри копии. Всё, что отличается от него,
сделал исполнитель — и ничего больше. Незакоммиченная работа владельца попадает
в этот коммит и потому никогда не будет выдана за чужую (сценарий G).

### Коммитить исполнителю незачем

Ему прямо сказано: достаточно оставить файлы в нужном виде, изменения соберёт
Бэрримор. Запрет на `commit` и `push` избавляет от попыток «довести до конца»
то, что заканчивать не ему.

Фраза «запрет обеспечивается изоляцией файловой системы» при записи не
показывается: там запись разрешена, и повторять её значило бы сбивать
исполнителя с толку.

### Применение — отдельное действие с проверкой до записи

`git apply --check --3way` выполняется до всякой записи: применить наполовину
хуже, чем не применить вовсе. Если каталог владельца ушёл вперёд и патч не
ложится, Бэрримор отказывается и говорит почему.

Ничего не коммитится. Изменения остаются незакоммиченными, чтобы владелец
посмотрел их своими инструментами и решил сам; откат — обычный `git checkout`.

### Судьба изменений отдельна от судьбы поручения

Поручение может быть выполнено, а изменения — ещё не рассмотрены.
`change_state`: `none` → `collected` → `applied` либо `discarded`. Пустой набор
изменений не ждёт решения: решать там нечего.

### Без git контролируемой записи не бывает

Нечем показать изменения и нечем их откатить. Это сказано прямо при запуске,
а не превращается в молчаливый провал на середине.

## Consequences

- подтверждение говорит не «с правом записи», а «с записью в копию каталога;
  изменения дойдут до вас только по вашему отдельному решению»: первая
  формулировка звучит так, будто исполнитель уже лезет в файлы владельца;
- в поручении появились `work_copy_path`, `work_copy_branch`,
  `work_copy_baseline` и состояние изменений; миграция 0010;
- дифф больше 512 КБ показывается обрезанным и не применяется отсюда: владельцу
  честно говорится, где лежит копия, вместо попытки наложить половину патча;
- в списке поручений дифф вычищается из ответа: сотня патчей по полмегабайта
  превратила бы обновление экрана в пересылку десятков мегабайт;
- запись включается явным `allow_write`; молчание запроса разрешением менять
  чужие файлы не является.

## Найденный дефект: git экранирует не-ASCII пути

Первый же тест с файлом «новый.go» показал, что при `core.quotePath=true`
(умолчание) git возвращает путь как `"\320\275\320\276..."`. Разбор такого
перечня молча терял файлы с русскими именами — то есть Бэрримор показал бы
владельцу неполный список изменений и умолчал бы об этом.

Исправлено: все вызовы git идут с `-c core.quotePath=false`.
