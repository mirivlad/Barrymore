# ADR 0011: Команды верификации — доверенный вход, отчёт worker — недоверенный

Status: Accepted
Date: 2026-08-04

## Context

`docs/08_API_AND_EVENTS.md` §6 помещает `verification_commands` в ContextPack —
тот же документ, который передаётся worker. `docs/06_SECURITY_AND_TRUST.md` §8
объявляет содержимое репозиториев и внешние тексты недоверенными. Если runtime
когда-либо возьмёт команду проверки из отчёта worker или из файла в проверяемом
репозитории, Verification станет вектором исполнения произвольного кода — и притом
самым привилегированным, потому что именно она решает, объявить ли работу успешной.

## Decision

Команды верификации берутся **только** из конфигурации Бэрримора и реестра проектов
(`~/.config/barrymore/policies.d/`, запись о workspace). ContextPack содержит их копию
для сведения worker, но runtime исполняет собственную запись, а не полученную обратно.

Отчёт worker влияет только на данные: он не может добавить, изменить или отключить
проверку. Расхождение между заявленным в отчёте и фактически проверенным фиксируется
как Discrepancy (сценарий J).

Каждая команда — argv-массив, без shell-интерполяции, с рабочим каталогом и таймаутом.

## Consequences

- `verification_commands` в ContextPack помечается как информационное поле;
- добавление проверки — изменение конфигурации, то есть действие пользователя;
- Verification исполняется в том же классе изоляции, что и worker;
- отсутствие настроенных проверок означает `unverified`, а не `passed`.
