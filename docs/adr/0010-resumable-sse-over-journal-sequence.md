# ADR 0010: Возобновляемый SSE поверх глобальной последовательности журнала

Status: Accepted
Date: 2026-08-04

## Context

`docs/03_SYSTEM_ARCHITECTURE.md` §10 задаёт SSE как транспорт, но не описывает
семантику переподключения. Без неё перезагрузка страницы или разрыв соединения
приводит к дыре в потоке событий — при том что проект отдельно требует честно
различать «связь потеряна» и «ничего не происходит».

## Decision

Каждое событие журнала получает глобальный монотонный `seq` (INTEGER PRIMARY KEY
AUTOINCREMENT). SSE отдаёт `id: <seq>`. При переподключении браузер присылает
`Last-Event-ID`, сервер доигрывает события из журнала и продолжает поток.

Один эндпоинт `/api/v1/stream` с фильтрами вместо отдельных SSE на сущность.

## Consequences

- потеря соединения UI не создаёт дыр в истории;
- тот же механизм обслуживает CLI (`barrymore watch`) и будущие интеграции;
- журнал становится буфером воспроизведения, отдельная очередь не нужна;
- retention журнала напрямую ограничивает окно возобновления — фиксируется в конфиге.
