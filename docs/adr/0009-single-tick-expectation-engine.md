# ADR 0009: Ожидания проверяются одним детерминированным тиком

Status: Accepted
Date: 2026-08-04

## Context

Ожиданий много, они долгоживущие и должны корректно восстанавливаться после рестарта
(`docs/02_DOMAIN_MODEL.md` §8). Реализация «горутина и таймер на каждое ожидание»
делает поведение зависимым от планировщика Go, теряет состояние при рестарте и
не поддаётся детерминированному тестированию.

## Decision

`expectations` содержит `next_check_at`. Один scheduler-цикл выбирает просроченные
строки пакетом и вызывает чистую функцию

```
Evaluate(exp Expectation, obs []Observation, now time.Time) Verdict
```

Побочные эффекты (создание Discrepancy, запуск probe, вызов reflex) выполняет
вызывающий код, а не функция оценки. Время во всём домене поступает через интерфейс
`Clock`; прямой вызов `time.Now()` в доменных пакетах запрещён и проверяется линтером.

## Consequences

- восстановление после рестарта — это просто «прочитать таблицу»;
- тесты expiry, cooldown и freshness детерминированы на fake clock;
- нагрузка предсказуема: один запрос на тик вместо N таймеров;
- пропущенные тики (простой процесса) обрабатываются штатно, а не теряются.
